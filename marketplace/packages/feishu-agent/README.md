# 飞书 Agent

飞书与 Codex CLI 当前会话之间的后台消息通道，并提供标记会话、日程任务的飞书交互卡片。普通飞书文字消息增量投递给 Codex；Codex 的输出与 Bridge 的结果回调转发到飞书。

## 连接

应用依赖飞书机器人、Codex CLI、日程、Agent Bridge 四个组件。组件或已绑定实例丢失时停止并报错；能力未连接或不可用时警告，实际调用失败保留记录，不终止后台。

在应用连接中设置以下能力：

| 别名 | 契约 | 用途 |
| --- | --- | --- |
| `feishuRead` | `polaris.feishu.read-messages@1` | 读取新增消息 |
| `feishuReply` | `polaris.feishu.reply@1` | 向飞书发送输出 |
| `codexGet` | `polaris.codex-cli.get@1` | 读取当前会话及完成输出 |
| `codexSend` | `polaris.codex-cli.send@1` | 增量输入 |
| `feishuActions` | `polaris.feishu.read-card-actions@1` | 读取卡片交互 |
| `feishuUpdateCard` | `polaris.feishu.update-card@1` | 更新原卡片 |
| `bridgeSessions` | `polaris.agent-bridge.sessions@1` | 读取标记会话摘要 |
| `bridgeResult` | `polaris.agent-bridge.result@1` | 读取会话最近已完成的回复 |
| `scheduleGet` | `polaris.schedule.get@1` | 读取日程任务与当前日期 |

四项飞书能力来自同一个实例，两项 Codex 能力来自同一个实例，两项 Bridge 能力来自同一个实例。使用前配置好 Codex 工作目录、模型和工具环境，启动应用并通过正常授权确认。

一个应用连接一个 Codex CLI 实例和一个飞书会话或话题。首次安装定位到飞书消息末尾，不重放旧消息；此后的第一条入站文字消息建立飞书连接。其他会话的消息会明确标记为未投递，不混入当前上下文。出站消息和非文字消息不回灌给 Codex。

## 飞书交互卡片（初版）

在已连接的飞书会话发送以下完整口令，或在本机应用点击“发送会话卡片”“发送日程卡片”：

- `面板`、`会话`、`标记会话`、`查看标记会话`（也支持 `/面板`、`/会话`）：打开标记会话卡片。
- `日程`、`查看日程`、`/日程`：打开日程任务卡片。

卡片顶部可切换两个页面；按钮筛选、翻页、详情与返回都更新同一条消息，每页 4 项。每次显示的按钮携带独立渲染标识，反复翻页、返回和刷新不会被当作同一次操作。卡片交互由独立线程每 150 毫秒读取，不与普通聊天发送串行等待；空轮询不重写状态文件。口令和卡片操作由应用直接处理，不发送给 Codex；其他文字仍走普通聊天。话题中的口令在原话题回复卡片。卡片记录和交互游标持久保存，重启不重发卡片。

会话按全部、运行中、在线、离线筛选，显示名称、状态、宿主、轮次数和工作目录。详情按需读取最近已完成一轮的回复，不把它当成正在运行一轮的结果。日程按今天、未来七天（含今天）、收集箱、全部未完成、已完成筛选，详情展示笔记及子任务。今天使用日程返回的日期；列表不把安排时间当成执行或提醒时间。长回复、笔记及子任务展示截短时明确标注。

初版为只读面板，点击“刷新”才重新读取最新数据；不修改任务或发送会话消息。新增读取与卡片更新能力需要在本机连接并确认授权。机器人需要启用 `card.action.trigger` 卡片回调。飞书 JSON 2.0 卡片的交互和更新有效期为 14 天，失效后可在本机待处理事项中跳过失败的卡片操作，再发送“面板”打开新卡片；应用不会自行按时限清空数据。失败原因在本机显示，可手动重试或跳过，不静默改发文字。

## 增量日程提醒

在「提醒设置」主动开启，并填写提醒偏好；默认关闭。规划范围为未来七天（包含第七天）的 Google 日历安排，以及截至该日期、有日期的未完成任务（含逾期任务，不含收集箱）。首次开启只规划此范围，不读取已完成任务历史。

- 每小时合并新增、相关字段变更及刚进入关注范围的事项，只将增量和这些事项已有的提醒记录交给 AI；无增量不调用 AI。「不提醒」也是已处理决策，不重复判断。
- AI 在已连接 Codex 当前会话的空闲回合生成提醒正文、发送时间与失效时间；不通过 steer 打断正在进行的聊天。规划期间新聊天暂存，完成后继续；规划 JSON 不转发到飞书。规划回合也保留在该原生会话上下文中。
- 提醒计划保存在本应用，不创建日程任务。到点读取最新日程，校验来源版本、状态、适用时间后直接投递飞书，不再调用 AI。
- 读取到取消、删除、任务完成时，立即作废待发送提醒；改期或重要内容变化时先作废旧计划，下一次小时检查再规划。不发送已发提醒的更正通知，不为近期新增事项额外唤醒 AI。
- 日程读取仍使用现有快照，程序比较增量后才交给 AI。Google 取消和改期以最近同步到本机的结果为准，不保证发送前实时向 Google 核实。设置展示 Google 最近同步时间与同步错误。
- 停止应用后不检查、不发送。重启保留增量与计划，过期提醒不补发；仍有意义的未完成任务交给下一次规划判断。发送失败沿用待处理队列；结果未知不自动重发，人工确认后再处理。重试前同样校验原事项。
- 修改提醒偏好或关闭提醒会作废旧待发送计划；AI 规划期间来源或偏好变化，旧版本结果不生效。开启后首次检查立即进行，此后按小时检查；等待当前 Codex 会话空闲时不设置总时限。

设置内可查看最近检查、最近规划、下次检查、待规划数量和提醒记录。读取或规划结果失败会显示原因并暂停提醒检查，处理后点击「继续」；无效的 AI 结果不会静默按「不提醒」处理，也不会发送到飞书。

## 持续会话与增量输入

应用使用 CLI 已有的原生会话，不调用新建会话接口。空闲时以 `start` 开始新回合，运行中以 `steer` 追加新增文字。每次只传本条新增正文，不拼接或重放历史。既有历史、处理结果及 compact 后的上下文由原生 Codex 会话保留；`/compact` 等文字命令交给 CLI 自身处理。

Codex 如何执行任务由其当前环境决定，包括对日程、Bridge 的使用。普通聊天不另设理解或决策环节；开启的日程提醒按上述独立增量规划流程执行。

## 输出与 Bridge 回调

应用以回合标识增量读取 Codex 的完成输出，持久化去重后发往已连接的飞书会话。首次接入不发送 CLI 已完成的历史输出；接入后、应用离线期间完成的输出会在恢复时继续处理。

应用声明 `bridge_output` 回调能力，契约为 `polaris.feishu-agent.bridge-output@1`。连接设置折叠区提供本应用的回调地址，可用于 Bridge `send` 的 `on_complete`：

```json
{"target":"本应用实例 ID","operation":"bridge_output","params":{}}
```

Bridge 返回的 `result` 必须包含 `deliveryId`、`sessionId`、`runId`、终态 `status`，以及可选的 `reply`、`replyTruncated`。应用保存输出后返回 `accepted: true`，表示已接管投递，不表示飞书已经收到。相同投递与回合的重复回调不会重复发送；相同标识但不同正文会报错。

回调输出只发往飞书，不作为 Codex 输入。用户在飞书回复后，才作为新的增量文字交给 Codex。调用回调入口仍须获得普通写权限；应用不会自动替调用方授予权限。尚未建立飞书连接时，已接管输出保留在队列中等待。

## 界面与失败处理

默认显示运行开关、连接与当前会话、卡片发送入口、待投递数量，以及需要人工处理的事项。成功历史、能力明细、回调地址不平铺；连接警告和具体原因在设置或单项详情中查看。

- 明确被拒绝的输入或输出保留为失败，可手动重试或跳过。
- 投递结果未知时不自动重发；核对 Codex 或飞书后，选择确认送达或确认未送达并重发。
- 读取失败后暂停该读取，处理原因后点击“继续”；不阻断已接管的 Bridge 输出。
- 切换页面不停止后台；停止或重启保留游标、输入、输出和去重标识，不自动重放已接受的输入。
- 旧版本的完整状态保留在 `legacy` 中。未完成任务只在用户选择“交给 Codex”后转交；旧发送结果未知的任务须先核对，不自动迁移投递。

## 离线测试

```sh
PYTHONPATH=next .venv/bin/python -m unittest discover -s next/applications/feishu-agent/tests -v
```

测试使用假的网络与 Codex transport，并覆盖原生 CLI 会话复用、增量 steer、compact、结果回调、去重、恢复、卡片口令分流、筛选分页、原卡片更新、跨会话隔离、权限失败和本机界面。额外使用实际 SDK 的交互去重管道验证 52 次重复翻页、返回、刷新和筛选，以及真正重投仍只处理一次；阻塞 Codex 发送时，卡片线程仍能独立更新。测试不调用真实模型或发送飞书消息。
