# 飞书 Agent

独立的北极星后台应用，将一个飞书机器人实例收到的文字交给一个 Polaris Agent 实例，再引用原消息回复。Agent 使用自己的当前模型配置。应用明确委托已绑定日程的 13 项操作和 Agent Bridge 的 8 项操作，作为模型可用工具。

## 安装与连接

在北极星的应用页面安装此目录，连接下列能力。飞书的 3 项能力必须来自同一个飞书实例，Agent 的 2 项能力必须来自同一个 Polaris Agent 实例；日程的 13 项操作必须来自同一个日程实例，Agent Bridge 的 8 项操作必须来自同一个 Bridge 实例。应用在启动时检查各组一致性，并显示实例与工具范围。

| 应用连接 | 能力契约 | 权限 |
| --- | --- | --- |
| 飞书连接状态 | `polaris.feishu.status@1` | 读取 |
| 读取飞书消息 | `polaris.feishu.read-messages@1` | 读取 |
| 回复飞书消息 | `polaris.feishu.reply@1` | 写入 |
| Agent 模型状态 | `polaris.agent.status@1` | 读取 |
| Agent 文本回复 | `polaris.agent.reply@1` | 写入 |

### 日程工具（13 项）

日程契约前缀为 `polaris.schedule`，版本为 `@1`；下表操作名中的下划线在契约名中改为连字符。

| 操作 | 能力 | 权限 |
| --- | --- | --- |
| `get` | 查看日程 | 读取 |
| `time_context` | 时间信息 | 读取 |
| `tasks` | 查询任务 | 读取 |
| `add` | 新增任务 | 写入 |
| `update` | 更新任务 | 写入 |
| `delete` | 删除任务 | 写入 |
| `undo_delete` | 恢复删除 | 写入 |
| `add_subtask` | 新增子任务 | 写入 |
| `update_subtask` | 更新子任务 | 写入 |
| `delete_subtask` | 删除子任务 | 写入 |
| `reorder` | 调整排序 | 写入 |
| `move_overdue` | 迁移逾期任务 | 写入 |
| `organize_day` | 整理当日日程 | 写入 |

### Agent Bridge 工具（8 项）

契约前缀为 `polaris.agent-bridge`，版本为 `@1`。

| 操作 | 能力 | 权限 |
| --- | --- | --- |
| `sessions` | 查询会话 | 读取 |
| `status` | 查询状态 | 读取 |
| `result` | 读取结果 | 读取 |
| `delivery` | 查询投递 | 读取 |
| `mark` | 标记会话 | 写入 |
| `unmark` | 取消标记 | 写入 |
| `send` | 发送任务 | 写入 |
| `requests` | 查询请求 | 读取 |

先在各组件中完成机器人连接与 Agent 模型配置，再点击应用的“开始运行”，确认这 26 项应用权限。另通过现有权限管理精确授予此应用目录组件的 `discover`、`describe` 两项读取权限，供 Agent 获取工具列表与参数说明。

应用根据上述 21 项工具的实际实例绑定，逐项构造 `allowed` 委托列表。飞书通道、Agent 自身与目录读取不加入模型工具列表。工具调用仍使用此应用获得的权限；升级保留原有 `state.json` 数据格式，无需迁移游标、队列或会话映射。

应用不会改变组件配置。停止运行后再次开启会继续保存的任务。

## 消息范围与会话

首次启动会完整翻页定位到当前消息末尾，忽略此前记录。此后只处理入站 `text`、`post` 消息中的非空正文，每条最多 8000 字。图片、文件、语音等附件不会送给模型；发送机器人自身消息的记录不会触发回复。

应用以飞书会话与话题的组合作为独立对话，生成稳定的 Agent conversation 标识。话题消息在对应话题中回复，普通消息引用原消息回复。Agent 的模型会话记忆由 Agent 组件管理，组件重启后不保留其内存上下文；应用自己的请求、回答和 conversation 映射会保留。

## 后台运行与失败处理

运行开关控制后台任务。切换页面或关闭应用视图后继续运行；退出北极星时停止。北极星再次启动时按已保存的运行意图恢复。机器人正在连接时，应用沿正常轮询等待并显示“连接中”，连接成功后才定位消息游标并处理请求；明确断开或连接错误需要处理后手动继续。停止时如果模型仍在生成，应用等待该调用结束并保存回答，不继续发送；用户再次开始运行后可以继续发送已保存的回答。

应用自己的数据目录保存 `state.json`：消息游标、完整请求队列、原始正文、模型回答、任务状态和会话映射。界面显示最近 40 条请求，以及更早但仍待处理的失败请求。消息获取游标与入队在同一次持久化中更新；同一会话或话题中，前面的失败请求处理完后才继续后续请求。

- **生成未完成**：查看错误，处理原因后点击“重新生成”；无法处理的请求可点击“跳过此请求”，保留记录并继续后续消息。
- **连接或读取失败**：处理组件状态或授权后点击“处理后继续”。不自动重试失败操作。
- **发送被拒绝**：组件明确报告权限、参数或飞书接口拒绝时，处理原因后点击“重新发送原回答”，不重复调用模型。
- **待核对发送**：应用无法确认飞书是否已收到回答。先在飞书中查看；已发送则点击“已在飞书确认发出”，确认未发送才点击“确认未发出，重新发送”。重新发送使用原回答，不重新调用模型。

进程在生成中断开时，该请求会保留为生成未完成；在发送中断开时，会保留为待核对发送。应用不会自动重发未知投递结果，也不会清空失败请求或原回答。

## 离线验证

在仓库根目录运行：

```sh
.venv/bin/python next/applications/feishu-agent/tests/test_backend.py
QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software .venv/bin/python next/applications/feishu-agent/tests/test_ui.py
```

测试使用假的应用上下文与模型、飞书响应，不调用真实模型或发送飞书消息。
