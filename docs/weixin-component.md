# 微信组件

Polaris 内置独立的微信 ClawBot / iLink 文字通信组件，直接用 HTTPS 连接微信后端。
无需安装 OpenClaw、运行机器人框架或配置公网回调。微信接收端使用服务端长轮询，
不是 WebSocket；所有请求异步运行，不阻塞 Qt 界面。

## 使用

1. 安装 `requirements.txt` 中的依赖，启动新版 Polaris。
2. 点击桌宠打开画布，第四格是微信；`↗` 打开完整视图，右键或托盘菜单也可打开。
3. 在手机微信“我 → 设置 → 插件”中启用 ClawBot（实际可用性取决于微信版本与账号）。
4. 点击“扫码绑定”，扫描组件二维码并在手机确认；如提示配对码，在组件内填写。
5. 从手机 ClawBot 会话发一条文字。收到后，可在组件底部手动回复绑定者。
6. “断开”停止接收并保留绑定；“连接”恢复；“退出登录”清除本机绑定和消息。
   本机退出不会承诺撤销腾讯侧凭证，需要完全解除时请同时在微信解除绑定。

默认使用鲸鱼娘人设进行 DeepSeek 自动回复，开关可关闭且会保存。
内置极简 Agent 循环，可在独立授权后调用 Polaris 组件；不接入终端、任意文件、群聊或联系人。
图片、文件等仅显示不支持提示，不下载附件。组件不向本地 MCP 注册任何操作，
因此现有 Agent 的组件授权不能读取微信消息或借此发消息。

## 生命周期与存储

- 正常启动自动连接已保存的微信绑定；诊断引擎不自动联网。画布隐藏或最小化不影响连接。
- 一次登录最多等待五分钟；取消、断开、重连、退出会取消旧请求并使旧回调失效。
- 网络错误指数退避重试，最长间隔一分钟；登录失效停止接收，需重新扫码。
- 接收长轮询的正常超时视为本次没有消息，不误报断连或关闭自动回复。
- 发送只允许绑定扫码者，必须先收到对方消息并取得会话 context token。没有任意目标参数。
- 单条发送最多 2,000 字符；本机保存最近 100 条显示消息，单条最多 8,000 字符。
- 最近 512 条消息 ID 去重，进度与凭证一起保存；从其他用户或群收到的内容不显示、不回复。
- 发送超时、断开或错误显示“结果未知”，不自动重发，请到微信确认。
- Windows 使用当前用户 DPAPI 加密、QSaveFile 原子写入 `weixin-account.dat`，
  与 `tasks.json` 同目录。保存 bot token、绑定身份、接收游标和去重 ID，
  不保存聊天正文、二维码和会话 context token。保存失败会显示提示。
- 非 Windows 暂只支持内存绑定，重启重新扫码；没有明文凭证降级。
- 仅允许 HTTPS 的 `weixin.qq.com` 及其子域服务地址，不跟随 HTTP 重定向，
  不把凭证转发到其他域名。界面始终按纯文本显示消息。

这是本机组件内部的 Qt 对象，并非低权限恶意插件的沙箱；同一 Windows 用户下的
恶意进程仍可能解密 DPAPI 数据。未来连接 Agent 时需要另行实现远程身份和操作授权。

## 实现与协议来源

- `polaris/weixin.py`：异步请求、扫码状态机、接收去重、手动回复与取消。
- `polaris/weixin_credentials.py`：凭证加解密与原子存储。
- `qml/components/WeixinPanel.qml`：画布与完整视图，共用同一模型。

协议参考腾讯官方仓库在 2026-10-29 的公开实现（兼容参考版本 2.4.10）：
[协议说明](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md)、
[API 实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/api/api.ts)、
[扫码登录](https://github.com/Tencent/openclaw-weixin/blob/main/src/auth/login-qr.ts)。
该说明描述客户端行为，不能替代完整服务端契约，后端变更需要跟进验证。

## 验证范围

临时内联诊断使用假 Qt 网络回复和临时目录，覆盖登录、配对码、消息过滤、去重、
手动发送、取消、旧回调丢弃、登录失效、重定向拒绝、Windows 加密恢复与退出清理。
另检查 QML 加载和本地二维码图像。真实腾讯接口已验证获取二维码；
真实扫码后的收发仍需账号持有人手机确认后进行。未读取真实聊天或修改已有绑定。

## DeepSeek V4.1 Flash 对话

Windows 和 Linux 均在启动时直接读取进程环境变量 `DEEPSEEK_API_KEY`。
不提供密钥输入框，不读写模型凭证文件，不自动读取 `.env`，也不回退到旧的
`weixin-model.dat`。Key 不回显、不放进提示词、不暴露给 MCP。
在本机环境中设置该变量后，从继承该变量的终端或启动器重新启动 Polaris；
已经运行的进程不会随外部环境变量修改而更新。Linux 桌面启动器或 systemd 服务也需
显式继承该变量，仅在另一个终端 export 不会改变它们的环境。
微信绑定凭证仍独立管理，不受此模型配置变化影响。

“测试连接”会单独调用一次 API，产生少量费用，不向微信发送测试回复。
首次使用默认自动回复；有有效环境变量 Key 且微信连接开始后，处理此后新收到的、
带有效时间戳的绑定者纯文字。手动关闭会保存，重启尊重关闭选择。
画布也显示自动回复开关与状态。时间戳兼容数字、数字字符串，以及消息项中的时间字段。
开启前或缺少时间戳的消息不会补发给模型；图片、语音、附件不转交模型，
引用只使用本条文字，不展开被引用内容。
断开或重启会取消待处理请求，不补发旧消息；重连后按保存的开关自动恢复。
模型或微信发送失败暂停本轮自动回复，不重试已失败消息；可点击“恢复自动回复”。
“新对话”只清空模型上下文，“清空消息”同时清空显示记录，二者均保留自动回复偏好。
退出微信清除该账号聊天记录。关闭不能撤回已经发出的请求或消息。

调用固定使用 `https://api.deepseek.com/chat/completions`、`deepseek-flash`，
非思考模式、非流式、最多 1,024 输出 token。普通会话可返回文字或 Polaris 工具调用，
连接测试只请求简短文字、不执行工具。
仅发送本轮文字、固定助手说明和最近最多 6 轮已确认发送的对话，
上下文最多 16,000 字符，保存在本机以便重启续聊；单条输入上限 4,000 字符。
生成结果最多 1,800 字符，超长注明截短；只发最终正文，不发送 `reasoning_content`。
输入与上下文会被发送给 DeepSeek，结果会自动回传微信并产生 API 费用。

同时只处理一轮，最多排队 3 条；每分钟最多 10 次自动模型请求。
网络、鉴权、余额、限流、响应格式或微信发送确认失败时关闭自动回复，
不自动重试收费请求或重发消息。模型请求禁止 HTTP 重定向，限制响应大小与总耗时。

`main.py` 组装微信客户端与聊天 Agent；`weixin.py` 只负责微信登录、凭证、消息与传输去重，
不创建或依赖模型。`deepseek_api.py` 负责模型 HTTP、Key、限流与请求取消；
`deepseek_chat.py` 负责自动回复、上下文、设置与工具循环，`chat_state.py` 负责持久化格式和原子写入。
聊天层通过公开的消息恢复与发送接口使用客户端，不直接修改客户端私有状态。
参考 [DeepSeek 官方接入说明](https://api-docs.deepseek.com/quick_start/agent_integrations/)
和 [Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)。
测试使用假网络和临时进程环境，覆盖环境变量缺失、非法格式、Windows/Linux 一致读取、
显式开启、旧消息过滤、队列与频率限制、已确认发送后写入上下文、取消旧请求、
鉴权失败、密钥与推理内容过滤。不读取真实 Key，也不发起真实收费请求。
设置环境变量并启动后，可通过“测试连接”核验账号实际可用性。

## 可配置人设与持久化

微信完整视图 → 模型设置可编辑“对话人设”，最多 6,000 字符；
“保存人设”即时生效，“恢复默认鲸鱼娘”恢复内置版本。修改人设清空旧的模型上下文，
保留可见聊天记录，避免旧角色语气继续进入提示词。未保存的人设和回复草稿在本次运行内保留，
返回画布再打开可继续编辑；不跨重启保存，也不会因关闭视图而自动提交或发送。

内置人设采用用户确认的社区女仆鲸鱼娘方向：软萌、轻微傲娇、嘴硬心软，爱白米饭、
偶尔摸鱼和天然呆，但认真回答实际问题。玩梗是语气，不作为拒绝做事或编造结果的理由。
可配置文本与固定的工具边界、独立授权和真实结果说明一同注入每轮系统提示。
参考项目素材署名、[社区角色卡](https://github.com/Neko3000/deepseek-whalechan/blob/main/README.zh.md)
和[社区性格来源梳理](https://www.ali213.net/news/html/2026-9/1044117.html)，不将其视为 DeepSeek 官方设定。

`weixin-chat.json` 与 `tasks.json` 同目录，保存人设、自动回复偏好、账号归属、
最近 100 条显示记录和最多 6 轮已确认发出的模型对话。不保存 API Key、微信 token 或 context token。
Windows/Linux 使用同一原子写入逻辑；Unix 新文件权限为 0600。聊天正文是本机 JSON 文本，
不声称加密。读取损坏或不支持的文件时停止自动回复、不覆盖原文件，并在界面提示。

聊天恢复必须匹配微信 bot ID 和绑定者 ID；未绑定时不显示上次聊天，重新扫码同一账号后
才恢复，换账号不继承上一账号的记录。重启前未确认发送的消息标为结果未知，不重发。
Linux 的微信登录凭证仍暂只保留在内存，重启需要重新扫码；人设、开关和聊天可持久化，
API Key 始终通过环境变量提供。

临时诊断验证默认人设进入请求、首轮新消息自动回复、人设编辑/恢复、开关重启保留、
确认发送后保存上下文、聊天恢复与去重、未确认发送标记、账号隔离、重新绑定后恢复和损坏保护。

## 极简 Polaris Agent

执行流程为模型 → 组件工具 → 工具结果 → 模型，直到得到最终文字，再发回微信。
通过构造时传入的 `ComponentRegistry` 直接调用，不启动 MCP 子进程或第三方 Agent 框架。
MCP/Pi 保持三个共享工具；微信 Agent 在 `polaris_components`、`polaris_help`、`polaris_call`
之外提供本机 `polaris_plan`，用于提交当前请求的完整写计划；`polaris_call` 只接受读取。
没有通用反射或 shell。
必须先读取组件 help，业务参数仍由组件自己的接口验证。

读取业务数据默认拒绝：在微信完整视图的“模型设置”内逐个勾选“允许读取”。
此授权只属于当前微信连接，不继承 Codex / Pi 连接权限，不写入持久化文件。
读取结果会进入 DeepSeek 上下文，模型可将其回复到绑定者微信。
授权单位是当前用户请求的完整操作计划，而非每次工具调用。
`write_plan.py` 校验计划及依赖，程序按所有步骤的实际操作判断风险，模型不能自行标记低风险。
业务参数由组件自己的无副作用 `prepare_write` 预校验并规范化，执行时也复用相同规则；
计划层不维护日程标题、日期、时间等校验副本。审批及计划去重使用规范化后的参数。
纯新增任务、子任务的首份计划默认自动执行；删除、覆盖、批量修改和未知操作需整份确认。
混合计划只要含需确认步骤，批准前连新增步骤也不会执行。
模型须先读取所需组件 help、查询目标真实ID，再提交 `polaris_plan({steps:[...]})`。
新建主任务与子任务可放在同一计划，子任务 `taskId:{"$ref":"parent.task.id"}`
仅引用前面 `id:parent` 的新建步骤结果；不允许前向引用、任意字段引用或执行时猜ID。
需要确认时，桌宠展示整份计划及固定参数，用户本机点击“批准整份计划”，
或在绑定者微信回复“批准 六位码”才执行；回复“拒绝 六位码”取消整份计划。
批准一次覆盖其全部步骤；追加动作或换目标须另交计划重新审批，包括后续新增动作。
“自动执行低风险计划”偏好默认开启，可在模型设置关闭，重启保留；已有待审批计划不因开启开关自动通过。
微信审批回执展示操作说明、参数，以及已查询主任务的标题、日期；参数过长时只允许本机完整查看后审批。
审批码使用安全随机数，仅绑定当前账号、当前待审批操作及不可变参数，回执确认送达后启用。
同一进程不复用审批码；输错5次停用本次微信审批，本机仍可审批。
审批消息由程序直接处理，不进入模型输入或待回复队列；普通“同意”不能批准。
审批两分钟过期；拒绝、关闭本轮或断连后失效。模型没有授权或批准工具。
待审批卡固定在微信组件顶部，不随聊天滚动；画布中点“查看并审批”进入完整视图核对参数。
等待审批时先向绑定者微信发送一次状态回执；最终回复等待该回执发送结束后再发送，
不会因发送通道正忙而丢失。回执不计入模型的已完成对话上下文。

模型工具调用 ID 不得重复；本机批准 ID 一次消费，重复点击或取消后的旧审批不会再执行。
本轮已执行、尝试或拒绝的同一计划不能重放；更换步骤名字不能绕过此限制。
计划执行失败、结果未知或保存报错时立即停止，返回每步结果及尚未执行的步骤，不自动重放或回滚已执行部分。
工具失败或超时不自动重放。每轮最多6次模型调用、8次工具调用、累计8个写计划步骤、5分钟总耗时，
每个模型返回最多4个工具调用，按顺序执行；每分钟最多10次模型请求（包含工具续轮）。
工具结果超过16,000字符时缩减返回，不把大结果误报为写入未执行。
工具调用、临时读取授权和待审批请求不跨重启恢复；只保存用户文字与最终已发出的文字。

用户给出的数字任务名默认是标题，例如“22”不等于内部ID 22。
微信 Agent 修改已有主任务前须当轮通过 task.list 查询实际ID；未在本轮列表结果出现的ID直接拒绝申请审批。
审批说明显示真实标题和日期，重名须先澄清日期。查询授权仍由本机单独授予，微信审批码不授予读取权限。

临时假网络测试覆盖发现/help/读取拒绝与授权、工具续轮、写操作批准/拒绝/失效、
审批单次消费、同参数独立审批、最终回复和断连撤权。未操作真实日程或通过测试向微信发送消息。

询问“有没有执行中/在跑的任务、会话”等实时状态时，微信 Agent 通过同一授权工具链
即时调用 `agents.session.status`，直接按实际状态生成带查询时间的摘要，不让模型沿用历史聊天猜数量。
这类常用状态命令不调用模型；未授权或读取失败会明确表示无法确认，不回复“没有任务”。
“现在呢”等连续追问同样重新读取；明确询问日程、待办或计划的问题仍走普通 Agent 工具循环。
