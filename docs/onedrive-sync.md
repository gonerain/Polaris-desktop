# OneDrive 日程同步（预览版）

本地优先。只有用户主动登录微软账号后，Polaris 才会访问 OneDrive；无需自建服务器。
这是 Polaris 自己的数据格式，**不能与 Super Productivity 互相同步**。

## 使用前

- 首次启用前备份本地 `tasks.json` 及 `.bak`。建议先用测试账号和测试任务验证两台设备。
- 同步主任务、子任务、日期、时间、完成状态、重点、排序、笔记；不上传聊天、微信凭证、Agent 会话或窗口布局。
- **云端文件是明文 JSON，尚无端到端加密**。HTTPS 只保护传输；不要用于未获准上传的敏感资料。
- 凭证只保留在进程内存，不写文件、不经过 AI；重启后需要重新登录。
- 不同设备必须使用同一个微软应用 Client ID、同一个微软账号。每台设备的 `onedrive-config.json` 是独立设备身份，**不要复制/网盘同步这个配置文件**。
- 只支持当前统一数据格式，不提供旧格式读取、迁移或降级路径。不支持的文件保持原样并停止写入，不会自动清空数据。

## 注册微软应用

需要自己注册应用，不复用 Super Productivity 的 Client ID，也不需要 Client Secret。

1. 在 Microsoft Entra 管理中心注册应用。
2. 支持账户类型选择组织账户及个人 Microsoft 账户（如只供组织内部使用，可按管理员策略配置）。当前实现使用 `common` 租户和全球微软云。
3. 在“身份验证”中启用 **允许公共客户端流 / Allow public client flows**，供设备代码登录使用。设备代码流程不需要本地回调地址。
4. 配置 Microsoft Graph 委托权限 `Files.ReadWrite.AppFolder`；登录时同时请求 `offline_access`，用于本次进程中的令牌刷新。不要添加应用程序级全盘访问权限。
5. 复制“应用程序（客户端）ID”。组织策略可能要求管理员批准或禁止设备代码登录；这类限制需要在租户侧处理。

官方说明：[设备代码登录](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code)、[应用专属文件夹](https://learn.microsoft.com/en-us/graph/onedrive-sharepoint-appfolder)。

## Polaris 中操作

1. 展开画布，在日程标题栏点击 `☁`；完整日程工作台也有同样入口。
2. 填入 Client ID，点击“登录并允许同步”。
3. 点击“打开微软登录页面”，在微软官网输入显示的登录码，审阅权限后确认。Polaris 不索取微软密码。
4. 登录成功后点击“立即同步”；也可启用“登录后每分钟自动同步”。默认不开自动同步。
5. 在另一台设备执行同样操作。断开只清除本次运行的令牌，不删除云端文件；彻底撤销授权需到微软账号的应用权限页面操作。

同步过程中编辑了本地任务时，本轮不会把下载结果覆盖到界面，会提示再次同步。已上传检查点会在下一轮安全合并。

## 合并规则

- 每个任务、子任务拥有持久 UUID；本地整数 ID 不上云，由接收设备独立分配，保留已有条目的本地 ID。
- 以**一项主任务（含其子任务、笔记、日期与排序）为合并单元**，使用设备计数构成的因果版本，不依赖系统时钟。
- 修改不同任务直接合并。相同任务的先后修改采用因果较新的版本。
- 同一主任务并发发生不同修改，保留两份，额外版本标题带“同步冲突副本”。当前不做字段级合并，所以即使分别修改两个子任务，也可能产生主任务副本。
- 删除与编辑并发时，保留编辑并提示冲突；明确看到远端编辑后再次删除，才会传播删除。删除墓碑暂不清理。
- 对冲突副本正常整理、删除即可，后续同步会传播整理结果。

## 存储与故障保护

本地 UUID、同步因果记录和任务一起通过 `QSaveFile` 原子提交到 `tasks.json`，沿用上个版本备份与损坏保护。任务文件统一使用 v3，UUID、同步因果记录与下一任务 ID 都是必需字段，不再按是否启用同步切换格式。应用远端结果前先完成持久化；失败不替换当前内存模型。

云端在 Graph 的 `approot`（应用专属文件夹）保存：

```
polaris-calendar-v1-<device UUID>-<20位检查点序号>-<随机UUID>.json
```

每次写新文件，不覆盖共享文件，不依赖小文件上传接口的 `If-Match` 行为；两台设备不会直接覆盖彼此的检查点。上传超时后不盲目删除/覆盖，下次同步读取云端事实。

列出文件后只下载每台设备最新的检查点；同序号分支都保留并合并。旧文件仅用于恢复，**首版不自动清理历史文件**，长期使用会增加存储和列表开销，需后续提供安全归档/回收机制。不要手工删除各设备最新检查点；不要在多个并发实例中复用同一设备配置。

首版边界：单包8MiB、单轮下载合计64MiB、最多500个设备/并列分支、最多50页目录；超过上限或遇到不兼容数据会停止，不回退覆盖本地。暂不支持世纪互联/其他主权云、后台关闭后同步、共享协作、加密、历史恢复界面和跨账号数据集隔离。换账号会把当前本地日程作为同一数据集参与新账号的同步，务必先确认上传范围。
