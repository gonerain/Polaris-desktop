# Polaris 组件平台设计

正式实现位于 `next/polaris_platform`。组件边界遵守 [README 的组件设计原则](../README.md#组件设计原则)；运行、SDK、权限与桌面视图的当前行为见 [开发说明](../next/README.md)，插件源和清单标准见 [组件契约](../next/CONTRACT.md)。

## 设计取舍

- 平台本身由运行管理、协作、授权、窗口承载、画布和桌宠等组件组成。启动配置绑定基础角色，普通组件不能通过声明同名身份获取管理权。
- 统一身份和公开契约，不要求把每个类或辅助库拆成组件。边界服务于独立开发、运行和替换；业务字段、状态及规则由提供方维护。
- 独立进程以 JSON 可表示的数据实现语言和依赖隔离；可信同进程原生视图可使用公开契约约定的 Python/Qt 类型。进程隔离不等于操作系统沙箱。
- 能力与展示分开。画布拥有布局，窗口承载拥有窗口资源，提供方拥有业务状态和原生视图；隐藏视图不停止组件。
- 动态加入、退出和能力声明变化均约束当前调用与授权。恢复能力不重放业务请求；停止失败须明确报告并由管理操作决定是否强制结束。
- 接口主版本、读写级别和授权修订号共同表达授权语义。平台依赖作者如实维护接口声明，不能自动证明隐藏的业务语义兼容。

## 当前实现与验收

平台支持本地目录和插件源安装、进程与同进程组件、持久安装身份与授权、事件协作及 Qt 原生视图。运行管理实现替换需要重启；授权与协作实现的运行中替换、能力退出恢复及撤权行为有测试覆盖。同进程任意线程和 Qt 对象不能保证安全卸载。

开发说明中的“边界与验收”列出对应测试、已验证的桌面行为和限制。实现变更继续按 README 的边界问题审查：公开契约不变时是否迫使调用方修改、退出后保留哪些能力、新增组件是否引入业务分支、业务规则是否仍由所属组件解释。
